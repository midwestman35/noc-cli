# Adopt Ruff (Format + Lint) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Adopt `ruff` as the repo's formatter + linter, normalize the existing codebase once, and wire a `PostToolUse` hook so every future `.py` edit is auto-formatted and lint-fixed.

**Architecture:** Add `ruff` to the `dev` dependency group with a conservative config in `pyproject.toml`. Apply formatting and autofixes to the whole tree in dedicated, isolated commits (kept separate from feature work so diffs stay reviewable). Then add a Claude Code `PostToolUse` hook (merged into the existing `.claude/settings.json` that already holds the protected-path `PreToolUse` hook) so edit-time formatting happens automatically. Finally, document the new commands in `AGENTS.md`.

**Tech Stack:** Python 3.10+, `uv` (lockfile + runner), `ruff` (Astral), Claude Code hooks (`settings.json`), pytest (regression safety net).

**Layer:** This is **Layer 1 (dev-time tooling)** only. Nothing here ships in the `noc-cli` package or changes the runtime Agent SDK workflow. The `[tool.ruff]` config in `pyproject.toml` is build-tooling metadata; it is not imported by the application.

---

## Decisions baked in (override before execution if you disagree)

- **Lint rules:** `E`, `F` (ruff defaults) + `I` (import sorting) + `UP` (pyupgrade). Deliberately excludes noisier families (`B`, `SIM`, `ANN`, …) — tighten later once adoption is stable.
- **Line length:** 88 (ruff default). **Target version:** `py310` (matches `requires-python = ">=3.10"`).
- **First normalization is split across commits** (format, then autofix, then manual remainder) so each diff has one clear cause.
- **No CI** in this plan. A GitHub Action running `ruff check` is a separate follow-up (recommendation #5).
- **`ruff` version:** `>=0.6` (no tight pin; let the lockfile capture the resolved version).
- **Pre-existing `bc9bb23` branch state:** plan assumes a clean working tree on `feat/interactive-tui-shell`. If uncommitted changes exist (e.g. the in-flight `watch_app.py` edits), commit or stash them first so the reformat commits are pure.

### Task 5: Resolve the remaining (non-autofixable) lint findings

**Files:**
- Modify: individual files with remaining findings, OR `pyproject.toml` (for justified per-file ignores)

- [ ] **Step 1: List what's left**

Run: `uv run ruff check .`
Expected: either `All checks passed!` (skip to Step 4) or a list of findings ruff could not autofix (e.g. `F401` unused import it won't remove because it's re-exported, `E501` long line, `F841` unused variable).

- [ ] **Step 2: Fix each finding at the source where reasonable**

For each finding, prefer fixing the code. Examples:
- Unused import that is a deliberate re-export → add it to `__all__`, or annotate the line:
  ```python
  from .models import Ticket  # noqa: F401  (re-exported)
  ```
- Genuinely long line `E501` → wrap it.
- Unused variable `F841` → remove it or prefix with `_`.

- [ ] **Step 3: For whole-category exceptions, use a scoped per-file ignore**

If an entire file legitimately needs an exception (e.g. generated/seed data, or a runbook loader with intentional star-imports), add to `pyproject.toml` rather than littering `# noqa`:

```toml
[tool.ruff.lint.per-file-ignores]
"noc_cli/seed.py" = ["E501"]
"tests/*" = ["F401"]
```

Only add ignores you can justify in the commit message. Do not blanket-ignore to silence real findings.

- [ ] **Step 4: Confirm a clean lint run**

Run: `uv run ruff check .`
Expected: `All checks passed!` (exit code 0).

- [ ] **Step 5: Run the test suite**

Run: `uv run pytest -q`
Expected: same pass count as Task 2 Step 3.

- [ ] **Step 6: Commit**

```bash
git add -A
```

### Task 6: Add the format-on-edit PostToolUse hook

**Files:**
- Modify: `.claude/settings.json` (merge a `PostToolUse` block alongside the existing `PreToolUse` protected-path hook — do NOT replace the file)

The existing `.claude/settings.json` currently contains only a `PreToolUse` hook. This task **adds** a sibling `PostToolUse` entry. Read the file first; preserve `PreToolUse` exactly.

- [ ] **Step 1: Pipe-test the raw hook command before writing it**

Run (substitute a real `.py` file from the repo):

```bash
cmd='f=$(jq -r ".tool_input.file_path // empty"); case "$f" in *.py) uv run ruff check --fix --force-exclude "$f" >/dev/null 2>&1; uv run ruff format "$f" >/dev/null 2>&1 ;; esac'
echo '{"tool_name":"Edit","tool_input":{"file_path":"noc_cli/cli.py"}}' | bash -c "$cmd"; echo "exit:$?"
```

Expected: exit 0, and `git status --short noc_cli/cli.py` shows no change (file was already formatted in Task 3). The `--force-exclude` flag makes ruff honor excludes even when given an explicit path. Then revert any incidental change: `git checkout -- noc_cli/cli.py`.

- [ ] **Step 2: Read the current settings file**

Run: `cat .claude/settings.json`
Expected: shows the existing `hooks.PreToolUse` array. Keep it.

- [ ] **Step 3: Write the merged settings.json**

The full file becomes (PreToolUse preserved verbatim; PostToolUse added):

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Edit|Write|NotebookEdit",
        "hooks": [
          {
            "type": "command",
            "statusMessage": "Checking protected paths…",
            "command": "f=$(jq -r '.tool_input.file_path // empty'); case \"$f\" in *.env.example|*.env.sample|*.env.template) ;; *.env|*/.env|*/.env.*|*.env.*|*/Tickets/*|*/.remember/*|*settings.local.json|*.db|*.sqlite|*.sqlite3) echo '{\"hookSpecificOutput\":{\"hookEventName\":\"PreToolUse\",\"permissionDecision\":\"deny\",\"permissionDecisionReason\":\"Protected path per AGENTS.md: .env / Tickets / .remember / settings.local.json / SQLite databases are off-limits to edits.\"}}' ;; esac"
          }
        ]
      }
    ],
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "statusMessage": "ruff format…",
            "command": "f=$(jq -r '.tool_input.file_path // empty'); case \"$f\" in *.py) uv run ruff check --fix --force-exclude \"$f\" >/dev/null 2>&1; uv run ruff format \"$f\" >/dev/null 2>&1 ;; esac; true"
          }
        ]
      }
    ]
  }
}
```

Note the trailing `; true` so the hook always exits 0 (PostToolUse is non-blocking — a lint finding must not abort the edit).

- [ ] **Step 4: Validate JSON syntax + both hook paths**

```bash
jq -e '.hooks.PreToolUse[].hooks[].command' .claude/settings.json >/dev/null && echo "PreToolUse OK"
jq -e '.hooks.PostToolUse[] | select(.matcher=="Edit|Write") | .hooks[].command' .claude/settings.json >/dev/null && echo "PostToolUse OK"
```

Expected: both print `OK` (exit 0). A malformed file silently disables ALL settings — if either fails, fix before continuing.

- [ ] **Step 5: Prove the hook fires and fixes a violation**

Introduce a formatting violation an editor wouldn't auto-strip (two consecutive blank lines inside a function are collapsed by ruff). Pick a small module, e.g. add two blank lines mid-function in `noc_cli/branding.py` via an Edit, then:

Run: `git diff --stat noc_cli/branding.py`
Expected: **no diff** — the PostToolUse hook reformatted the file back immediately after the edit. If a diff remains, the hook didn't fire: open `/hooks` once (reloads config) or restart Claude Code, since the settings watcher only tracks `.claude/` if a settings file existed at session start.

Clean up: `git checkout -- noc_cli/branding.py`.

- [ ] **Step 6: Commit**

```bash
git add .claude/settings.json
git commit -m "chore(ruff): add format-on-edit PostToolUse hook"
```
